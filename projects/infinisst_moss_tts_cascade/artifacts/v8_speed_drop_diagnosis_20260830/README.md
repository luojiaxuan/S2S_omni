# v8 在 1.5× 掉分的归因（2026-08-30）

问题：v8 phrase-matched TTS 在 1.5× 的 BLEU 是 29.61，比 1× 的 34.09 低 4.48。
直觉上 1.5× 每个 turn 的文本更长（26.1 字 vs 20.4 字），TTS 应该更好。

用现成评测产物（HF `gavinlaw/infinisst-moss-tts-en-zh-multiturn`
`eval/phrase-matched-tts-v8-20260830/`）做的分解，纯 CPU，无需重跑。

## 1. 不是某个 talk 的问题

| talk | 1× | 1.5× | 差 |
| --- | ---: | ---: | ---: |
| 110 | 36.53 | 34.54 | −1.99 |
| 117 | 30.79 | 25.45 | −5.34 |
| 268 | 32.84 | 27.46 | −5.38 |
| 367 | 36.70 | 31.48 | −5.22 |
| 590 | 34.75 | 30.38 | −4.37 |
| 合计 | **34.09** | **29.61** | **−4.48** |

talk117 在 1.5× 贡献了 34 个 null 中的 28 个（幻觉出播客开场白），但去掉它
之后差距只从 −4.48 变成 −4.23。**五个 talk 全都掉，是系统性的。**

（复算合计 34.09 与报告的 34.0855 一致，口径无误。）

## 2. 不是 ASR 的问题

把送进 TTS 的原文与该 turn 单独 ASR 的结果逐字比对：

| | 中位字错率 | p90 | 字错率>50% 的 turn |
| --- | ---: | ---: | ---: |
| 1× | **0%** | 37.5% | 75 个（8.5%） |
| 1.5× | **0%** | 97.1% | 99 个（14.0%） |

**两档中位字错率都是 0%**——ASR 在正常 turn 上准确。损失全部来自尾部。

## 3. 真正的原因：TTS 停不下来

最差的几个 turn 是同一个形态——**短输入、超长音频**：

| 送入 TTS | 字数 | 生成音频 | ASR 转写 |
| --- | ---: | ---: | --- |
| `例。如您所见，` | 5 | **14.72s** | `例，如您所见，这种事这里成功可以导致这种事例就会隐于这例的体前提跟随` |
| `二、句子标注器。` | 6 | **14.96s** | `二句子标注器按胶在肩前照库，以词性标注和解码照库器，刚链类尼过于三岛` |
| `双语者所做的事情。` | 8 | **13.44s** | `双语者所做的事情，代码转换是双语者所做的事情。代码转换是装机不分相待` |

TTS 收到几个字却生成十几秒音频，自己往下编；ASR 只是忠实转写了它实际说的。

以「秒/字 > 0.6」为失控判据（正常水平见下）：

| | 秒/字 p50 | p90 | p99 | 失控 turn | 失控占音频 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1× | **0.231** | 0.314 | 0.997 | 30（3.4%） | 382s（10.6%） |
| 1.5× | **0.231** | 0.425 | 1.400 | 40（5.6%） | 513s（13.6%） |

**两档的正常发音速率完全相同（0.231 秒/字）**，差别只在失控比例：3.4% → 5.6%，
占用音频 10.6% → 13.6%。

## 4. 关键发现：长 delta 完全消除失控

失控 turn 按输入长度分布：

| 输入长度 | 1× 失控数 | 1.5× 失控数 |
| --- | ---: | ---: |
| ≤5 字 | 1 | 2 |
| 6–15 字 | 17 | 21 |
| 16–30 字 | 12 | 17 |
| **31+ 字** | **0** | **0** |

**31 字以上的 turn 在两档都零失控。** 逐 turn 字错率也随长度单调下降
（1×：37.4% / 18.0% / 15.7% / **7.7%**）。

这从数据上支持「text delta 越多、TTS 质量越好」，并且给出了具体阈值：
**把 delta 推到 31 字以上，失控就消失了。**

## 5. 结论与建议

- v8 的 1.5× 掉分**不是** InfiniSST 文本变差、也**不是** ASR 不行，
  而是 **TTS 在部分 turn 上失控生成**，且该比例在 1.5× 上更高。
- 因此**应该在 v8 基础上继续迭代**，方向是把 write 做得更长，而不是更早释放。
  （此前基于「碎片导致音色跳变」提出的早释放规则 B 与该目标相反，已作废；
  音色跳变的真因是 codec decoder 跨 turn 未保留历史，已另行解决。）
- 待查：为何 1.5× 的失控率更高。两档 TTS 模型与解码参数相同，唯一变量是
  输入文本，故应比较两档失控 turn 的文本特征（是否更多罕见词/不完整短语）。
