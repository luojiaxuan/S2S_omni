# 发审前的自我判断：v9 write policy 设计（2026-08-30）

**在 ChatGPT 外审之前写下，防止外审变成背书。**

## 用户提议

去掉「等标点」这条规则，改为：
- `multiplier ∈ {1,2,3,4}` 决定 chunk 大小（multiplier × 0.96s），是延迟/长度的主旋钮；
- 只加一个 `min_words` 约束（至少多少字），可扫，默认先取 2；
- 不再有 `max_hold`、不再有标点判定。

## 我的判断：认同，且比现设计更好

**理由一：它消掉了现设计最坏的一类样本。** 当前规则有 13.4%（m=1）/
**25.8%（m=2）** 的 write 是被 `max_hold` 强制切断、不以任何标点结尾的半截短语
——「phrase boundary」这个前提在四分之一的监督样本上根本不成立。新设计没有
`max_hold`，这类样本消失。

**理由二：它把两个启发式阈值换成一个可扫的物理量。** 现设计有
`phrase_max_hold_s` + `phrase_min_chars` + 标点集合三个启发式；新设计只剩
chunk 大小（有物理含义：延迟预算）+ 一个防退化下限。审稿人攻击面小得多。
`min_words` 的存在理由是明确的：避免 1 字 write 浪费一次 TTS turn。

**理由三：实测证据不支持「标点边界」的必要性。** 我原以为半截短语会诱发 TTS
续写，实测证伪：1.5× 档里**以标点结尾的 turn 失控率反而更高**（7.1% vs 1.6%）。
所以标点约束买不到它声称的东西。

## 我的保留意见（两条，都应进实验设计而不是否决提案）

**保留一：`min_words=2` 可能把 delta 做得太短，与「delta 越长 TTS 越好」冲突。**
实测每字错误率随长度单调下降：1-5 字 37.4% → 6-15 字 18.0% → 16-30 字 15.7%
→ 31+ 字 7.7%（1× 档）。若 min_words=2 且 multiplier 小，write 会退回 baseline
的碎片形态。**长度的控制权实际上落在 multiplier 上**，min_words 只是下限保护。
因此扫描必须是 multiplier × min_words 的二维，不能只扫 min_words。

**保留二：BLEU 不足以做这次扫描的判据。** 1.5× 掉分的真因是 TTS 超额生成
（超额>3s 的 turn：1× 6.0% → 1.5× 11.4%，占音频 11.3% → 17.5%），而超额率
**在 16-30 字区间最高**（1×: 8.5%，1.5×: 13.6%），不是单调的。所以存在最优
长度区间，扫描必须把「超额生成率」作为一等指标同时报，否则会选到一个 BLEU
看着还行、但 TTS 频繁失控的点。

## 我建议的实验设计

- 扫 `multiplier ∈ {1,2,3,4}` × `min_words ∈ {1,2,4,8}`，纯 CPU 先出
  write 长度分布与延迟分布（无需训练）；
- 用已有的 v8 评测数据拟合「write 长度 → 每字错误率 / 超额生成率」，
  在扫描结果上预测级联质量，选 2-3 个点再真训；
- 保留一个对照臂：「有标点则在标点处切，否则照写」（软偏好，不等待），
  用来验证标点是否还有剩余价值——它几乎不花延迟。
